# 花火街 1.1.50（ベータ・花火音圧と屋外反射）

本人が1.1.49をQuest 3で確認し、花火と本体を両方100％にしても音量が物足りないと報告しました。余韻は少し改善し、尺・二尺はトンネルのように聞こえなければ、もっと長いビルからの反射を残してよいという判断です。今回は花火の増幅と大玉の屋外反射を調整します。1.1.50の聴感の採否は、Quest実機でこれから確認します。

花火側に固定6倍（約15.6dB）の増幅段を追加しました。音楽はこの段を通りません。初期60％・上限100％と保存済み音量は保持し、その同じ表示でも従来より大きな出力を得る構成です。花火用コンプレッサーの閾値を-9→-6dB、ニー9→6dB、比率8→12、アタック3→1ms、リリース0.20→0.15秒に変更し、低い音の増幅を保ちつつ、増幅後のピークと多重発音を制御します。コンプレッサー後に0.88倍の出力余裕を設けました。最終MIXの約0.98までの波形ガードは保持します。大玉・多重発音では制限が働くので、実際の出力や聴感を一律6倍と表現しません。

3号の録音波形と音色は維持します。5号以上の発射・開花だけ、1800Hzから上の成分を1.5dB持ち上げる控えめな調整を追加しました。録音が必ずこもるという原因の断定ではなく、輪郭を少し出す試作です。音程・長さ・切出しと録音の選択、全26点のJS配列は同じです。

5号の短い余韻は1.1.49と同じです。尺・二尺だけは開花から0.65／0.75秒後まで送りをゼロ、その後0.25秒で主音の20％を薄く入れます。そこから0.18、0.33、0.57、0.91、1.36、1.92、2.62、3.24秒の不規則な位置に、広い帯域の短い反射の塊を配置し、後ほど弱く・高域を控えめにしています。左右に僅かな時刻差を付け、密な低音リバーブや等間隔の反復エコー、フィードバックは使いません。反射用バッファは3.8秒です。主録音の後半から送るので、開花から3.8秒で全体を切る意味ではありません。

カムロの尾が規則的に聞こえるという追加の本人報告を受け、短い録音の並び替えも修正しました。旧処理は140msごとの継ぎ目でほぼ無音へフェードし、元と隣接区間に対する継ぎ目の平均エネルギー比が約0.005でした。今回、95～210msの不規則な区間を14～24ms重ねてつなぎ、同じ位置の平均比は約0.457まで回復しました。尾を1.5倍に伸ばす処理も44～78msの不規則な刻みにしました。6種類の準備済みバリエーションと休止再開時の同じ選択を保ち、千輪の子玉にも同じ不規則な接合を使います。これは継ぎ目の周期的な落ち込みを改善した計算結果で、自然な聴感の保証ではありません。

各玉の録音バリエーション、5号の滑らかな減衰、二尺の低音、千輪の大小差、カムロの尾の長さと入り尺1.5秒／二尺2秒、笛0.5秒と6録音、街・屋形船、二尺中心高度2.00と上昇時間、3曲の順番「花火の夜 → 夏の名残 → パステル・パラサイト」と時刻は保持しています。全花火は共通の増幅を通るため、副次音も音量は上がります。素材26点のJS配列配信と、個別の効果音ファイル・書き出し機能を付けない方式も保持します。

実アプリのXR・船・曲・休止再開・笛・高さ・音量操作と保存設定、全録音波形の一致、Chrome Web Audioで全開花録音・発射・多重発音・最大音量・音楽20％MIX・HRTF位置・笛千輪カムロトラの複合・予約取消・実パステル曲末の最後の二尺、38ファイル3曲のオフライン保存と失敗時復旧を確認しました。出力計算はQuestの自然さ・実機負荷・本体60〜70％で十分な音量かの保証ではありません。

Questで「オフライン保存を確認・更新」から保存し、「保存済み1.1.50」→再読み込み→左上1.1.50を確認してください。まず本体60〜70％・花火60％で、曲なしの一玉と連発、尺・二尺の反射を聴き、その後音楽20％と曲末の最後の一発を確認してください。
